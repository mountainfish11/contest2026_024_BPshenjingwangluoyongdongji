# 连续 ASR 网络故障核查（2026-10-16）

## 范围

ESP32-S3-EYE 主板，USB MAC `a4:cb:8f:e1:e0:80`。本次未烧录子板。
目标是处理连续录音识别时，前两次正常、随后出现网络错误的问题。

## 证据与修改

- 录音清理曾跳过定长录音缓冲的释放，每轮约增加 17 KB 堆占用。
  `apps/system/nxrecorder/nxrecorder.c` 现在释放录音器持有的 APB 引用；
  I2S 异步回调仍持有独立引用。
- ASR 连接清理后曾遗留 CLOSED、ref=0 的 TCP 项。
  `packages/ai_agent/src/voice/volc_asr.c` 改用 `mbedtls_net_close`，
  避免在 NuttX 上先异步 shutdown 再 close。修改后观察到连接与 IOB 回收。
- 上述回收修复后仍有 TLS 超时。故障期间 TCP 数据未确认并重传；
  主副板 TCP 也出现重连，网关 ping 曾达 4230 ms。
- 不录音，只执行百度 HTTPS 对照测试，也复现前两次 HTTP 200、第三次失败，
  同期网关 ping 丢包，说明故障不局限于录音或火山鉴权。
- 单独关闭 TX AMPDU 仍复现握手超时。
  同时关闭 TX/RX AMPDU 后，下述八轮连续测试未复现网络故障。
  这是已验证的配置规避，尚不能据此断言无线底层的具体根因。

已在当前 `.config`、`nuttx/defconfig` 和主板 `configs/blindbadge/defconfig`
保存禁用 TX/RX AMPDU 的配置；启用 `CONFIG_NET_STATISTICS` 供资源诊断。
未保留扩大网络回调池的试验。

## 真板连续测试

烧录后通过不复位 USB 的串口脚本执行八轮：

```text
blind_badge_app voice_asr 3 &
```

每轮完成 198400 字节 I2S 采集，转换为 48000 个 16-bit 单声道采样，
向服务上传 96000 字节 PCM。八轮均完成 TLS、WebSocket 和音频上传，
未出现连接重试、TLS 超时或网络错误。

| 轮次 | 服务结果 |
| --- | --- |
| 1、2、4、5、7、8 | 未检测到语音，返回 `-ENODATA`（-61） |
| 3、6 | 返回非空中文识别文本 |

第一轮及第六、七、八轮结束时堆占用均为 323280 字节；
第五轮暂为 341704 字节，下一轮恢复。未再观察到每轮约 17 KB 的持续增长。

测试结束后：按键服务为 RUNNING、状态 IDLE、网络已连接；
IOB 为 124/124 空闲，TCP 表仅剩主副板的正常连接，没有遗留 ASR 连接。
网关 ping 三次均为 30 ms，未丢包。

编译、主板烧录及镜像哈希校验通过；三个相关仓库的 `git diff --check` 通过。

## 验证边界

以上是串口命令触发的真实麦克风与云端 ASR 测试，不是八次物理按键测试。
“未检测到语音”证明收到服务结果，不计为识别文字成功。
两轮非空文字未与现场说话内容逐字核对，不能据此评价准确率。
仍需用户连续短按 BOOT 并说话，复核物理按键入口及现场识别效果。
